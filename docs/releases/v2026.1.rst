Gluon 2026.1
============

Important notes
---------------

Upgrades are only supported from v2023.2 and later.

This release is based on the OpenWrt 25.12 release branch, using the following components:

- Linux 6.12
- mac80211-backports 6.18
- batman-adv 2025.4


Introduction of APK
-------------------

OpenWrt 25.12 uses ``apk`` as its package manager. A quick reference guide
for ``apk`` can be found in the MOTD when connecting via SSH as well as in
the `OpenWrt documentation <https://openwrt.org/docs/guide-user/additional-software/opkg-to-apk-cheatsheet>`__.
To save flash space, ``apk`` is disabled by default on ``tiny`` class devices.

For signing the generated ``apk`` package repository, OpenWrt 25.12 uses ECDSA keys stored at
``openwrt/private-key.pem`` and ``openwrt/public-key.pem`` (in addition to ``openwrt/key-build*``
for firmware image signatures). Communities that persist signing keys across builds must back up
and restore these ``.pem`` files as well.

Since ``apk`` version comparison rules differ from ``autoupdater``, ``contrib/compare-versions.sh``
has been added to replace ``opkg compare-versions`` when testing ``DEFAULT_GLUON_RELEASE`` ordering.


Site changes
------------

.. _#3852: https://github.com/freifunk-gluon/gluon/pull/3852

- The introduction of APK requires renaming the ``opkg`` section in ``site.conf`` to ``apk``.
  Note that repository URLs in ``apk.openwrt`` and ``apk.extra`` must **not** end with a trailing
  slash (or ``packages.adb``), as ``/packages.adb`` is appended automatically, and custom mirrors
  must serve an APK index instead of an ``opkg`` feed.
- Unlike ``opkg``, OpenWrt 25.12 fails the build when deselecting non-existent packages
  (``-pkgname``) in ``image-customization.lua`` (such as ``-opkg``, ``-wpad-basic``, ``-wpad-mini``,
  or ``-kmod-ipt-offload``).
- The obsolete ``ffda-network-setup-mode`` community package is now rejected at build time in favor
  of ``gluon-network-setup-mode`` (`#3852`_).

Features
--------

.. _#3602: https://github.com/freifunk-gluon/gluon/pull/3602
.. _#3701: https://github.com/freifunk-gluon/gluon/pull/3701
.. _#3736: https://github.com/freifunk-gluon/gluon/pull/3736
.. _#3777: https://github.com/freifunk-gluon/gluon/pull/3777
.. _#3791: https://github.com/freifunk-gluon/gluon/pull/3791
.. _#3832: https://github.com/freifunk-gluon/gluon/pull/3832
.. _f10732fb: https://github.com/openwrt/openwrt/commit/f10732fb5632091452c5b091d3bbd3102d1148da

- Add basic support for 6 GHz Wi-Fi, including client bridge configuration and radio statistics
  (`#3602`_)
- Expand BATMAN_V integration with throughput reporting, algorithm-specific status-page metrics,
  and ``gluon-radv-filterd`` support (`#3736`_)
- Add network-triggered Config Mode activation (``gluon-network-setup-mode``) for devices without a
  reset button (`#3852`_)
- Give network interfaces on x86 persistent names based on PCI address (``enpXsY``) or MAC address
  (``enxXXXXXX``) and preserve interface roles across upgrades (`#3832`_)
- Extend the status-page to allow navigation elements for community-specific subpages (`#3701`_)
- Allow Meshtastic multicast traffic to pass the mesh multicast filter (`#3777`_, `#3791`_)
- mac80211 now estimates the available throughput of wireless links which use rate control
  offloading (`f10732fb`_)

Known issues
------------

.. _#94: https://github.com/freifunk-gluon/gluon/issues/94
.. _#496: https://github.com/freifunk-gluon/gluon/issues/496
.. _#1728: https://github.com/freifunk-gluon/gluon/issues/1728

- BATMAN_V: Throughput values are not correctly acquired for different interface types (`#1728`_)

  This affects virtual interface types like bridges and VXLAN.

- Default TX power on many Ubiquiti devices is too high, correct offsets are unknown (`#94`_)

  Reducing the TX power in the Advanced Settings is recommended.

- In configurations without VXLAN, the MAC address of the WAN interface is modified even when
  Mesh-on-WAN is disabled (`#496`_)

  This may lead to issues in environments where a fixed MAC address is expected (like VMware when
  promiscuous mode is disallowed).
